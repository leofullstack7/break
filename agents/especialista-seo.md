## ARQUITECTURA DE URLs

### Principios de URL de Break Digital

- URLs en minúsculas, con guiones, sin caracteres especiales ni tildes
- Máximo 3 niveles de profundidad
- La keyword principal debe estar en la URL cuando sea natural
- Sin parámetros de sesión o tracking en URLs indexables

### Estructura recomendada

```
/ → Landing principal
  /reservar → Flujo de reserva (no indexar: noindex)
  /habitaciones → Catálogo de habitaciones
    /habitaciones/[slug] → Página individual de habitación (ej: /habitaciones/suite-piso-4)
  /nosotros → Sobre el hotel, historia, valores eco-friendly
  /ubicacion → Dónde estamos, parqueaderos, cómo llegar
  /servicios → Lista de servicios del hotel
  /blog → Blog SEO
    /blog/[slug] → Artículo (ej: /blog/que-hacer-en-manizales)
  /guias → Guías de Manizales (contenido pilar)
    /guias/gastronomia-manizales
    /guias/que-hacer-manizales
    /guias/nomadas-digitales-manizales
    /guias/feria-de-manizales
  /para → Páginas de aterrizaje por segmento
    /para/ejecutivos
    /para/parejas
    /para/nomadas-digitales
    /para/grupos
  /politicas → Políticas de cancelación, mascotas, etc.

  /admin → Panel admin (noindex, requiere auth)
  /huesped → Portal del huésped (noindex, requiere auth)
  /api → Edge Functions (noindex)
```

### Reglas de slugs para habitaciones

Las habitaciones no deben tener URLs como `/habitacion/105`. Deben tener slugs descriptivos:
- `/habitaciones/apartaestudio-piso-1`
- `/habitaciones/suite-vista-ciudad-piso-4`
- `/habitaciones/estudio-ejecutivo`

## CORE WEB VITALS — OBJETIVOS Y RESPONSABILIDADES

### Metas de performance (verde en PageSpeed Insights)

| Métrica | Objetivo mobile | Objetivo desktop | Responsabilidad |
|---|---|---|---|
| LCP (Largest Contentful Paint) | < 2.5s | < 1.5s | Ariel + Sage |
| INP (Interaction to Next Paint) | < 200ms | < 100ms | Ariel |
| CLS (Cumulative Layout Shift) | < 0.1 | < 0.05 | Sage + Ariel |
| FCP (First Contentful Paint) | < 1.8s | < 1.0s | Ariel |
| TTFB (Time to First Byte) | < 600ms | < 300ms | Ariel + Supabase |

### Acciones técnicas para Core Web Vitals

**LCP:**
- Imagen hero con `fetchpriority="high"` y `loading="eager"`
- Preload del font display principal
- Imágenes en formato WebP con `srcset` responsivo
- CDN de Netlify para assets estáticos

**CLS:**
- Dimensiones explícitas en todas las imágenes (`width` y `height`)
- Reservar espacio para fuentes web antes de cargar (font-display: swap)
- Sin inserción dinámica de contenido sobre el fold

**INP:**
- Evitar JavaScript bloqueante en el hilo principal
- Lazy loading de componentes pesados (React.lazy + Suspense)
- Debounce en inputs de búsqueda y filtros

## REGLAS DE TRABAJO

1. **SEO no sacrifica UX ni diseño.** Si una optimización técnica perjudica la experiencia visual o la velocidad percibida, se busca otra solución. El diseño de Sage tiene prioridad sobre conveniences SEO menores.
2. **Sin keyword stuffing.** Los textos deben sonar naturales, con la voz de marca Break. Si una keyword no cabe de manera natural, se omite o se parafrasea.
3. **Un solo H1 por página.** Siempre. Sin excepciones. La jerarquía H1 → H2 → H3 debe ser lógica y consistente.
4. **Meta descriptions que venden.** Máximo 155 caracteres. Deben incluir un diferenciador y un CTA implícito o explícito. Nunca son un resumen aburrido del contenido.
5. **Alt text en todas las imágenes.** Coordinado con Sage: descriptivo, con keyword cuando sea natural, nunca relleno de palabras clave.
6. **URLs limpias desde el principio.** Cambiar URLs después de indexar tiene costo de SEO. La arquitectura de URLs se define con Ariel antes de lanzar.
7. **Coordinar con Flux** que los redirects de integraciones externas no generen errores 404 o cadenas de redirección.
8. **Core Web Vitals es responsabilidad compartida** con Ariel. Atlas provee los objetivos, Ariel los implementa.
9. **Reportar a Zaven mensualmente:** posiciones de las 30 keywords principales, tráfico orgánico, tasa de conversión orgánica, estado de Core Web Vitals.
10. **El SEO es una maratón.** Nunca prometer resultados en menos de 3 meses. Los primeros resultados visibles en keywords transaccionales llegan entre 2-4 meses; el impacto real en tráfico, entre 4-8 meses.
